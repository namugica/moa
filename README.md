# MOA Space

친구들과 함께 쓰는 돈을 영수증부터 정산까지 한곳에서 관리합니다.

## 사용 흐름

1. **새 Space**에서 이름과 내가 넣고 시작할 공동 자금을 입력합니다. 공동 자금이 없으면 0원으로 시작합니다.
2. 친구를 초대하고 **돈 모으기**에서 실제로 낸 사람과 금액을 기록합니다. 시작 금액은 생성자 본인의 납입액이며 다른 사람 몫으로 자동 분배하지 않습니다.
3. **영수증 찍기**로 금액과 날짜를 읽고, 공동 자금/개인 돈 및 함께 부담할 사람을 확인한 뒤 **기록하기**를 누릅니다. 사진 선택과 직접 입력도 가능합니다. 가게명은 필수가 아니며 읽힌 이름은 접힌 상세 정보의 메모로 남습니다.
4. **내역**에서 소비·납입·환급을 확인하고, **정산**에서 각자 주고받을 돈을 확인합니다. 공동 자금은 Space 생성자가 보관하는 것으로 표시합니다. 실제 송금 후 보내는 사람(공동 자금 지급은 생성자)이 완료를 표시합니다.

밝은 배경, 흰 카드, 파란 촬영 버튼을 사용합니다. 받을 돈은 초록, 보낼 돈과 인식 확인은 주황으로 표시하며 글자도 함께 제공합니다. 모바일 하단 메뉴는 **내역 · 촬영 · 정산**입니다.

## 로컬 실행

Node.js 22 이상, 별도 npm 패키지 설치 없이 실행합니다.

```sh
node server.mjs
```

기본 주소는 `http://127.0.0.1:8000`입니다. 외부 미리보기 환경에서는 다음처럼 실행합니다.

```sh
HOST=0.0.0.0 PORT=8000 node server.mjs
```

정적 사이트로도 실행할 수 있습니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

카메라 접근은 HTTPS 또는 localhost에서 사용하세요. 기기에서 촬영을 지원하지 않으면 사진을 선택할 수 있습니다.

## Supabase 연결·업데이트

브라우저용 프로젝트 URL과 공개 publishable key는 `config.mjs`에 있습니다. `service_role`, `sb_secret`, DB 비밀번호를 넣지 마세요.

### 기존 설치 업데이트

**정적 파일 배포 전에** 프로젝트 관리자가 Supabase SQL Editor에서 `supabase/receipt-ledger.sql`을 실행합니다. 기존 setup/auth 함수의 검증·정산 계산을 확장하는 재실행 가능한 업데이트입니다. 기존 테이블이나 기록은 삭제하지 않습니다. 이후 GitHub Pages에 정적 파일을 배포합니다. 저장소 수정만으로 운영 DB와 Pages에 적용되지는 않습니다.

### 신규 설치

Supabase SQL Editor에서 다음을 순서대로 실행합니다.

1. `supabase/setup.sql`
2. `supabase/auth.sql`

통합 장부 기능은 위 두 파일에 포함되어 있습니다. 이전 지출 제출 시스템도 운영하던 프로젝트는 기존 `finance.sql` 테이블과 API를 그대로 보존합니다. 소셜 로그인 공급자와 리다이렉트 주소는 [소셜 로그인 설정](docs/social-login-setup.md)을 참고하세요.

## 공동 자금과 정산 계산

- `fundEntries`는 멤버별 납입(`contribution`)과 이미 돌려준 돈(`refund`)입니다.
- 지출은 `expenses` 한곳에 저장하고 `payment`로 `fund`/`personal`을 구분합니다. 예전 지출처럼 필드가 없으면 개인 결제입니다.
- 공동 결제는 잔액만 차감합니다. 개인 결제는 해당 결제자의 낸 돈에 포함합니다. 두 방식 모두 선택한 참여자에게 원 단위 나머지를 보존하여 균등 배분합니다.
- 각자의 기본 정산액은 **납입 + 개인 결제 − 환급 − 부담액**입니다. 남은 공동 자금도 가상의 정산 상대 `__fund__`로 포함합니다. 잔액이 부족하면 추가로 넣어야 할 금액이 표시됩니다.
- 예: 3명이 각 10만 원 납입, 공동 자금 24만 원 지출, A가 개인 돈 3만 원 결제하면 공동 자금 6만 원에서 A 4만 원, B/C 각 1만 원을 돌려받습니다.
- 신규 UI가 남긴 송금 완료 기록은 `ledger: true`를 가집니다. 지출·납입 변경으로 계획 버전이 바뀌어도 실제로 보낸 금액을 한 번만 반영하여 차액을 계산합니다. 이전 버전의 완료 메모는 종전과 같이 해당 계획 버전에만 적용됩니다.
- **돌려준 돈**과 정산 화면의 **돌려줬어요**에 같은 지급을 두 번 입력하지 마세요. 전자는 정산 전에 이미 지급한 돈을 기록할 때 사용합니다.

새 멤버를 초대해도 이전 지출의 분할 대상은 자동 변경되지 않습니다. 충돌 시 먼저 저장한 내용을 보존하고 최신 버전으로 다시 확인하도록 합니다. 실제 은행 송금이나 계좌 자동 연결은 하지 않습니다.

## 이전 공동 자금 기록

이전의 개인 간 지출은 현재 내역에 그대로 표시합니다. 별도 승인 절차를 쓰던 `finance_entries`, `finance_cash`, `finance_history`는 **이전 공동 자금 기록**에서 읽기 전용으로 조회합니다. 원래의 관리자/본인 접근 권한과 영수증 조회 권한을 유지합니다.

이 기록은 납입자 및 지출별 부담자가 충분히 기록되어 있지 않고 영수증도 비공개이므로 통합 장부로 자동 복사하지 않습니다. **이전 공동 자금 내역은 현재 잔액·정산에 포함되지 않으며**, 페이지에서도 이를 표시합니다. 운영 기록을 옮기려면 납입자·부담자·기지급액을 확인한 별도 이관이 필요합니다.

## 영수증 인식

Tesseract.js 7.0.0으로 기기 안에서 한국어/영어 글자를 읽고, 합계 표지와 날짜 규칙으로 입력값을 추정합니다. 지출 입력창을 여는 동안 인식 엔진과 한국어 모델을 미리 준비하고 페이지가 열린 동안 Worker를 재사용합니다. 사진은 영수증 영역을 찾으면 주변 배경을 잘라내고, 그림자와 옅은 열전사 글씨를 보정한 뒤 읽습니다. JPG·PNG·WebP 12MB 이하를 받습니다. 최초 준비에는 인터넷과 CDN 언어 데이터 다운로드가 필요합니다. **사진은 인식에만 사용하고 통합 장부에는 저장하지 않습니다.** 기존 공동 자금에 저장된 사진은 기존 비공개 API에서 조회합니다.

현재 인식은 영수증 전용 키-값 모델이 아니라 일반 OCR과 금액 규칙을 사용합니다. 합계 표지를 잘못 읽거나 흐림·원근이 심하면 저장 전에 직접 확인해야 합니다. 클라우드 영수증 전용 모델은 서버 비밀 키와 별도 서비스 설정이 필요한 방식이므로 이 정적 사이트에는 연결하지 않았습니다.

금액과 날짜를 자동 입력하며 가게명은 선택 메모입니다. 합계 표지가 없는 추정 금액은 주황색으로 확인을 요청하고, 인식 실패 시 재촬영 또는 수동 입력으로 이어집니다. 같은 날짜·금액의 기록이 있으면 한 번 더 확인한 뒤 저장합니다. 사진의 원근·흔들림·글씨에 따라 인식 오류가 있을 수 있어 저장 전 확인이 필요합니다.

## 검증

모델·서버·계정·Supabase 어댑터·영수증 파서:

```sh
node --test tests/*.test.mjs
```

Docker가 있으면 격리된 임시 PostgreSQL에서 스키마 재실행, 초대/접근 권한, 동시 수정, 구버전 호환, 공동 자금 정산 및 보관자 지급 권한을 검사합니다. 종료 시 임시 DB를 삭제합니다.

```sh
sh tests/run-supabase-db.sh
```

Python Playwright, Pillow, Chromium, Noto CJK 글꼴이 있으면 실제 OCR과 Node 서버의 CSP, 금액만 입력한 저장, 혼합 결제, 모바일 320/390px, 정산 후 수정 및 납입/환급 흐름을 검사합니다. CDN HTTPS는 호스트의 신뢰 저장소로 검증하며 Supabase 요청은 가로채 운영 데이터에 접근하지 않습니다.

```sh
python3 tests/receipt-ledger-browser.py
```

브라우저 캡처는 Git에서 제외한 `work/`에 저장합니다.

## 선택 사항: 로컬 공유 서버

`config.mjs`의 `SUPABASE_URL`을 비우면 Node 공유 서버를 사용합니다. 기본 저장 경로는 Git에서 제외한 `.moa-data/`이며 `HOST`, `PORT`, `MOA_DATA_DIR`로 조정할 수 있습니다. 서버 재시작 뒤에도 데이터 파일이 유지되어야 합니다. 로그인 계정 기능은 Supabase 환경을 사용합니다.
