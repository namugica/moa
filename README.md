# MOA

모아장부는 친구들과 함께 쓴 지출을 기록하고, 각자 부담할 금액과 주고받을 송금을 정리하는 공동 장부 서비스입니다. 장부와 지출은 함께 확인하고 편집할 수 있으며, 정산 내역에서 송금 계획과 완료 상태를 공유합니다. 화면은 GitHub Pages, 공유 데이터는 Supabase에 저장합니다.

## 시작하기

저장소에서 별도 패키지 설치 없이 로컬 화면을 실행할 수 있습니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8000`에 접속하세요. JavaScript 모듈을 사용하므로 HTML 파일을 직접 열지 말고 HTTP 서버를 이용합니다. `node server.mjs`로도 화면을 실행할 수 있습니다.

로그인하지 않고 만든 장부는 현재 브라우저에 저장됩니다. 친구들과 함께 쓰려면 카카오 또는 구글 로그인을 설정한 뒤 로그인하고, 프로필을 만든 다음 장부를 공유하세요.

## Supabase 최초 연결

`config.mjs`에 프로젝트 URL과 공개 publishable key가 설정되어 있습니다. 이 공개 키는 브라우저용입니다. `service_role`, `sb_secret` 키나 데이터베이스 비밀번호를 이 파일에 넣지 마세요.

1. Supabase 프로젝트의 **SQL Editor → New query**에 `supabase/setup.sql` 전체 내용을 붙여 넣고 **Run**을 누릅니다. 기존 다른 앱의 테이블을 변경하지 않으며, 다시 실행할 수 있습니다.
2. 변경된 소스를 GitHub Pages에 배포합니다. 기존 `https://namugica.github.io/moa/` 주소를 그대로 사용합니다. 별도 Node 서버 호스팅은 필요하지 않습니다.
3. 두 브라우저나 두 기기에서 로그인하고 장부를 만든 뒤, 친구 초대 → 참여 → 지출 추가가 되는지 확인합니다.

공유 데이터는 비공개 `moa_private` 스키마에 저장합니다. 테이블에 직접 접근할 권한은 공개 역할에 부여하지 않습니다. 공개 API 함수 `moa_api`가 장부별 멤버 토큰을 검사하고 권한이 있는 데이터만 반환합니다. SQL 실행용 관리자 권한은 공개 키에 포함되지 않으므로 최초 설정과 업데이트 적용은 프로젝트 관리자가 `supabase/setup.sql`을 SQL Editor에서 다시 실행해야 합니다. 로그인 계정 기능을 사용한다면 이어서 `supabase/auth.sql`도 다시 실행합니다.

장부 화면의 연결 상태는 **공유 중**으로 표시됩니다. 공유 기능을 사용하려면 인터넷 연결과 Supabase 프로젝트 가동이 필요합니다. Supabase 요금제의 요청량·가동 제한이 적용됩니다.

## 로그인 설정

로그인, 프로필, 계정별 장부 복구와 공통 초대 링크를 사용하려면 기존 `setup.sql` 다음에 **`supabase/auth.sql`**을 적용하고 Supabase에서 카카오와 구글 OAuth 공급자를 활성화해야 합니다. 자세한 콘솔 설정과 정확한 콜백 URL은 [소셜 로그인 설정](docs/social-login-setup.md)에 정리했습니다. 공급자 Client Secret은 Supabase에 직접 입력하며 브라우저 코드에 넣지 않습니다.

친구는 초대 링크를 열어 카카오 또는 구글로 로그인하고 자기 프로필로 참여합니다. 같은 계정은 기기가 바뀌어도 같은 멤버로 복구되며, 같은 이름의 다른 계정은 합쳐지지 않습니다. 프로필 이름을 바꿔도 지출의 멤버 ID와 정산 기록은 유지됩니다.

## 친구와 공동 장부 사용하기

1. **로그인**에서 카카오 또는 구글로 로그인하고 최초 프로필을 설정합니다.
2. **장부 만들기**를 눌러 모임이나 여행에서 함께 쓴 돈을 기록할 장부를 만듭니다.
3. 장부의 **친구 초대**를 눌러 공통 링크를 복사해 단체 채팅방에 보냅니다.
4. 친구들은 링크를 열고 로그인한 뒤 자기 프로필로 참여합니다.
5. 장부에서 **지출 추가**를 눌러 결제 내용, 금액, 결제자와 부담할 멤버를 입력합니다.
6. **송금할 내역**에서 개인별로 보낼 금액과 받을 사람을 확인합니다. 송금자는 송금 후 자신의 내역에서 **보냈어요**를 눌러 완료로 기록할 수 있습니다.

공통 링크는 7일 동안 여러 계정이 사용할 수 있습니다. 초대 화면을 다시 열면 같은 유효한 링크를 보여줍니다. 초대는 장부를 만든 사람만 할 수 있고, 참여자는 모두 장부 기록을 편집할 수 있습니다. 새 멤버는 이전 지출의 분할 대상에 자동 추가되지 않습니다.

지출은 선택한 멤버끼리 원 단위까지 균등 분할합니다. 결제자와 실제 부담자는 다를 수 있습니다. 장부 화면에는 함께 쓴 금액, 나의 보낼 금액, 받을 금액, 송금 완료액과 남은 금액이 표시됩니다. 완료 상태는 모든 참여자가 함께 확인할 수 있습니다. 완료 표시는 송금자가 직접 남긴 기록이며 MOA가 실제 송금 여부를 확인하거나 은행 송금을 실행하지는 않습니다. 지출이 수정되거나 삭제되면 과거 완료 기록은 새 정산 계획에 적용되지 않습니다.

동시에 수정하면 먼저 저장한 변경을 보존합니다. 뒤의 저장에는 충돌을 알리고 최신 데이터를 보여주며 입력값을 유지합니다. 확인 후 다시 저장할 수 있습니다. 연결이 끊겨 저장하지 못한 변경을 저장 완료로 표시하지 않습니다.

## 이전 여행 장부와의 호환성

이전 브라우저 전용 여행 장부는 초대할 때 계정에 연결할 수 있습니다. 기존 개별 초대도 로그인 후 수락할 수 있습니다. 기존 멤버를 계정에 연결하면 그 멤버의 브라우저 전용 참여 토큰은 폐기합니다.

기존 장부에 입력된 여행지·날짜, 여행 상태와 일정 기능은 호환성을 위해 남아 있습니다. 일정에 연결된 지출도 장부에서 독립 기록으로 유지되며, 일정을 삭제해도 연결된 지출은 삭제되지 않습니다. 실제 지출과 예상 비용은 별도로 표시합니다. 새 장부와 서비스 이용의 중심은 공동 지출 기록과 개인별 정산입니다.

## 데이터와 접근 권한

로그인하지 않고 만든 개인 장부는 해당 브라우저에 저장됩니다. 계정 장부와 프로필은 Supabase에 저장되며 계정용 API는 Supabase가 검증한 사용자 ID로 참여 권한을 확인합니다. 로그인 세션은 브라우저에 보관하고 갱신합니다. OAuth는 PKCE를 사용하고 로그인 복귀 후 일회용 코드를 주소에서 제거합니다. 로그아웃 시 계정 장부를 화면과 브라우저 전용 장부 저장 목록에서 제외합니다. JSON 내보내기에 인증 토큰은 포함하지 않습니다.

새로 만든 공유 장부는 로그인 계정에 연결됩니다. 기존 브라우저 전용 참여 방식은 이전 여행의 마이그레이션을 위해 유지합니다. 같은 이름만으로 다른 계정이나 수기 멤버와 합치지 않습니다. 서로 다른 이메일의 계정을 직접 합치는 화면, 계정 삭제·탈퇴·권한 회수는 아직 포함하지 않았습니다.

외화 환산·사진 업로드·푸시 알림·공개 코스 검색·JSON 가져오기는 구현하지 않았습니다.

## 테스트

Node.js 22 이상에서 모델, Supabase 어댑터 및 로컬 서버 테스트:

```sh
node --test tests/*.test.mjs
```

Docker가 있으면 실제 PostgreSQL에서 스키마 재실행·접근 차단·일회용 초대·공동 편집·동시 수정 충돌·분할 검증을 실행할 수 있습니다. 테스트는 격리한 임시 DB에서 실행하고 종료 시 제거합니다.

```sh
sh tests/run-supabase-db.sh
```

Python Playwright와 Chromium이 설치된 환경에서는 모의 소셜 로그인과 여러 브라우저의 전체 흐름도 확인할 수 있습니다. 테스트의 Supabase 요청을 임시 PostgreSQL RPC로 연결하며 **실제 Supabase 프로젝트에 테스트 데이터를 보내지 않습니다**.

```sh
MOA_BROWSER_TEST=1 sh tests/run-supabase-db.sh
```

Chromium 경로가 다르면 `CHROMIUM_PATH`를 지정합니다. 실시간 외부 서비스 검증은 별도로 프로젝트 접근이 가능한 환경에서 수행해야 합니다.

## 선택 사항: 로컬 Node 공유 서버

기존 Node 저장 방식도 개발·검증용으로 남겨두었습니다. 사용하려면 `config.mjs`의 `SUPABASE_URL`을 빈 문자열로 설정한 뒤 `node server.mjs`를 실행합니다. 기본 포트는 8000, 파일 저장 경로는 Git에서 제외한 `.moa-data/`입니다. `HOST`, `PORT`, `MOA_DATA_DIR`로 변경할 수 있습니다. 이 방식은 SSE로 연결되며 서버 재시작 뒤에도 데이터 파일이 남아야 합니다. 공개 배포에는 HTTPS·영구 저장소와 단일 서버 인스턴스가 필요합니다.
