# Moa Space

Moa Space는 동아리에서 발생한 지출을 제출하고, 관리자가 승인한 뒤 공동 자금과 환급 내역을 관리하는 공간입니다. 지출과 처리 이력을 참여자와 함께 확인할 수 있습니다. 화면은 GitHub Pages에서 제공하고, 계정과 공유 데이터는 Supabase에 저장합니다.

## 시작하기

저장소에서 별도 패키지를 설치하지 않고 로컬 화면을 실행할 수 있습니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8000`에 접속하세요. JavaScript 모듈을 사용하므로 HTML 파일을 직접 여는 대신 HTTP 서버를 이용합니다. `node server.mjs`로도 실행할 수 있습니다.

로그인 없이 만든 기존 장부는 현재 브라우저에 저장됩니다. 동아리 공동 지출 기능을 사용하려면 로그인하고 계정에 연결된 장부를 이용하세요.

## Supabase 설정

`config.mjs`에는 브라우저에서 사용하는 프로젝트 URL과 공개 publishable key가 설정되어 있습니다. `service_role`, `sb_secret` 키나 데이터베이스 비밀번호는 브라우저 코드에 넣지 마세요.

Supabase 프로젝트의 **SQL Editor → New query**에서 다음 SQL 파일을 순서대로 실행합니다.

1. `supabase/setup.sql`
2. `supabase/auth.sql`
3. `supabase/finance.sql`

기존 프로젝트도 정산 SQL의 변경 사항을 반영하도록 `setup.sql`을 다시 실행하세요. 회계 기능 SQL은 기존 정산 데이터를 그대로 두고 추가됩니다. SQL 실행 후 변경된 소스를 배포합니다. 저장소 변경만으로 실제 Supabase 데이터베이스나 GitHub Pages가 자동으로 바뀌지는 않습니다.

공유 데이터는 비공개 `moa_private` 스키마에 저장됩니다. 공개 역할은 테이블에 직접 접근할 수 없으며, API가 로그인과 장부 참여 권한을 확인합니다.

## 로그인 설정

로그인, 프로필, 계정별 장부 복구와 초대 기능을 사용하려면 `supabase/auth.sql`을 적용하고 Supabase에서 카카오와 구글 OAuth 공급자를 설정해야 합니다. 콘솔 설정과 콜백 URL은 [소셜 로그인 설정](docs/social-login-setup.md)을 참고하세요. OAuth 공급자의 Client Secret은 Supabase에 입력하며 브라우저 코드에는 넣지 않습니다.

## 동아리 지출 관리하기

1. 관리자가 로그인하고 장부를 만듭니다.
2. **친구 초대**에서 공통 링크를 복사해 동아리 참여자에게 공유합니다.
3. 참여자는 링크를 열고 로그인한 뒤 자신의 프로필로 참여합니다.
4. **지출·공동 자금** 탭에서 지출 이름, 금액, 사용 날짜, 목적, 분류와 결제 방식을 입력해 제출합니다.
5. 영수증 사진을 첨부합니다. 사진이 없다면 미첨부 사유를 입력해야 합니다.
6. 관리자는 제출 내용을 검토해 승인·보완 요청·반려합니다. 보완 요청을 받은 참여자는 내용을 수정해 다시 제출할 수 있습니다.
7. 승인된 지출은 결제 방식에 따라 공동 자금 잔액 또는 환급 대기 내역에 반영됩니다.

장부를 만든 계정이 관리자이며, 초대로 참여한 계정은 참여자입니다. 관리자는 모든 제출 내역을 보고 처리할 수 있습니다. 참여자는 자신의 제출 내역과 관련 지급 내역을 확인할 수 있습니다. 새 장부의 관리자 권한을 다른 계정으로 넘기는 기능은 제공하지 않습니다.

공통 초대 링크는 7일 동안 여러 계정에서 사용할 수 있습니다. 초대는 장부를 만든 사람만 할 수 있습니다.

## 영수증과 지출 검토

영수증은 JPG·PNG·WebP 형식의 사진을 첨부할 수 있으며 최대 크기는 1.5MB입니다. 사진은 비공개 데이터베이스에 저장되고 공개 사진 URL이나 공개 Storage 버킷을 사용하지 않습니다. 제출자와 관리자만 영수증을 조회할 수 있습니다.

관리자는 제출된 지출을 승인하거나 보완 요청 또는 반려할 수 있습니다. 보완 요청과 반려에는 사유가 필요합니다. 보완 요청된 내역은 제출자가 수정해 다시 제출할 수 있으며, 승인된 지출은 직접 수정할 수 없습니다. 처리 이력에는 제출, 검토, 지급 및 입출금 기록이 남습니다.

날짜·이름·금액이 같은 제출은 중복 의심 항목으로 표시될 수 있습니다. 이는 중복 여부를 확인하라는 안내이며 자동으로 제출을 차단하지는 않습니다.

## 공동 자금과 환급

관리자는 공동 자금의 입금과 기타 출금을 기록할 수 있습니다. 통장과 자동으로 연결되지 않으므로 실제 입출금 내역을 직접 기록해야 합니다.

공동 자금으로 결제한 지출은 승인되면 공동 자금 잔액에서 차감됩니다. 개인 돈으로 결제한 지출은 승인 후 환급 대기액에 포함되고, 관리자가 실제 지급을 마친 뒤 **지급 완료 기록**을 남기면 대기액과 잔액에 반영됩니다. 이 기록은 실제 송금을 실행하거나 은행 이체를 확인하지 않습니다.

승인된 지출이나 환급을 기타 출금으로 다시 입력하지 마세요. 지출 비용과 지급 내역은 별도로 계산되어 비용을 중복 반영하지 않습니다. 잔액이 부족해도 실제 지급 기록은 남길 수 있어 잔액이 음수로 표시될 수 있습니다.

회계 기능은 로그인한 계정에 연결된 장부에서 사용합니다. 기존 개인 간 정산 기록을 회계 지출로 자동 이관하거나 중복 반영하지 않습니다.

## 기존 장부와의 호환성

기존 여행 장부의 여행지·날짜·일정 기능은 호환성을 위해 남아 있습니다. 일정에 연결된 지출은 일정을 삭제해도 독립 기록으로 유지됩니다.

기존의 개인 간 정산과 송금 기록도 유지됩니다. Moa Space의 주요 사용 흐름은 동아리 지출 제출, 관리자 검토, 공동 자금과 환급 관리입니다.

## 데이터와 접근 권한

로그인하지 않고 만든 기존 개인 장부는 해당 브라우저에 저장됩니다. 계정 장부와 프로필은 Supabase에 저장됩니다. 로그인 세션은 브라우저에 보관하고 갱신하며 OAuth는 PKCE를 사용합니다. JSON 내보내기에 인증 토큰은 포함하지 않습니다.

## 테스트

Node.js 22 이상에서 모델, Supabase 어댑터 및 로컬 서버 테스트를 실행합니다.

```sh
node --test tests/*.test.mjs
```

Docker가 있으면 격리된 임시 PostgreSQL에서 SQL 적용, 권한, 초대, 공동 편집 및 회계 기능을 확인할 수 있습니다. 테스트용 데이터베이스는 종료 시 제거됩니다.

```sh
sh tests/run-supabase-db.sh
```

Python Playwright와 Chromium이 설치된 환경에서는 모의 로그인과 여러 브라우저의 흐름도 확인할 수 있습니다. 다음 명령은 지출 제출, 보완 요청, 영수증, 승인, 입출금, 지급 기록, 새로고침 및 모바일 화면을 검사합니다.

```sh
MOA_FINANCE_BROWSER_TEST=1 sh tests/run-supabase-db.sh
```

이 테스트는 임시 PostgreSQL을 사용하며 실제 Supabase 프로젝트에 테스트 데이터를 보내지 않습니다. Chromium 경로가 다르면 `CHROMIUM_PATH`를 지정하세요.

## 선택 사항: 로컬 Node 공유 서버

기존 Node 저장 방식은 개발·검증용으로 남아 있습니다. 사용하려면 `config.mjs`의 `SUPABASE_URL`을 빈 문자열로 설정한 뒤 `node server.mjs`를 실행합니다. 기본 포트는 8000이며 파일은 Git에서 제외된 `.moa-data/`에 저장됩니다. `HOST`, `PORT`, `MOA_DATA_DIR`로 설정을 바꿀 수 있습니다. 이 방식은 SSE를 사용하며 서버 재시작 후에도 데이터 파일이 보존되어야 합니다.
